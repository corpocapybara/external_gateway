**GitLab writes and MR fields missing, so GitLab work falls back to the browser** (2026-11-04). 379 browser
calls, 38 sessions, 111 `/api/v4/projects/…` fetches. `gitlab.mr_update` takes only `description`, so it can't
retarget (`target_branch`). No op opens a new (diff) discussion, since `gitlab.mr_note` only replies to an existing
one. `gitlab.mr` doesn't return `merge_method`, `squash` or `diverged_commits_count`. Group MR lists by
`author_id` also went through the browser (0ec2bbfd, 10-15).

**Refined 2026-11-12 against the gitignored thp ops.** Already there: a new diff discussion is
`gitlab.mr_discussion_create` (POST `.../discussions` with `position`, granted to dev-bot); group MR lists filter by
author through `gitlab.group_mrs` `author_username`, but only mr-worker holds that op. Missing: retarget
(`gitlab.mr_update` sends only `description`), the MR merge fields, and `merge_method`, which GitLab keeps on the
project (GET /projects/:id `merge_method`: merge, rebase_merge, ff), not on the MR. GitLab docs checked: PUT MR
accepts `target_branch`; GET MR returns `diverged_commits_count` only with `include_diverged_commits_count=true`.
All changes are in gitignored `operations.thp.yaml` / `config.thp.yaml`, like T0017; the delivery commit records them.
