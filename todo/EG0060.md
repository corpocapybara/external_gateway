From C:/dev T0023 (2026-11-17). New core rule "UI work is tested in the real app" (.ai/shared/rules/core.md
"Tests stay quick"; todo.md "Test runs"): a change a user sees in the app's UI is tested in the running app, started
the way its user starts it, over its real backend and data; a browser harness or stubbed backend does not count.

Add a short "how to run and drive the app" note: how an agent starts the ExternalGateway desktop app
(cmd/egw-desktop), how it drives it for the run-app check, and what data/backend it needs.

Refinement (2026-11-20), checked against the code:
- Not covered yet. README.md "Via ExternalGateway.exe (desktop app)" (README.md:108-139) describes the app for a
  person (double-click, tabs, tray) and README.md:37 the build line; nothing says how an agent starts a test build,
  finds the UI URL or which parts need computer-use.
- The UI is a local web page served by the app itself: `http://127.0.0.1:<port>/?s=<session>` (main.go uiURL),
  opened in an Edge `--app` window (win.go openWindow). Port and session are written to `<data-dir>\instance.json`
  (main.go:104-105); the page sends the session as `X-Session` (ui.html:103-107). So opening that URL in Chrome
  shows the real app over its real backend, not a harness.
- Single instance per data dir (win.go acquireSingleInstance): a second start only asks the running one to reopen
  its window (main.go signalRunningInstance), so a freshly built exe would not run while the owner's instance is up
  (one was running at refinement time, from the repo root). Hence the default start after the owner quits theirs,
  or `--data-dir <scratch> --tray` (random port, read from instance.json) if they keep it.
- Tray menu, notifications and icon colour live in tray.go: computer-use only.
- Admin actions go through an elevated helper (elevate.go, ShellExecute "runas" in win.go) and UAC.

Placement: the note goes in .ai/DEVELOPMENT.md (lazy-loaded) with a one-line pointer in AGENTS.md, to keep the
always-loaded file lean. Docs only: no code change.

For the implementer (refine round 2 notes): the exe is -H=windowsgui, so start it with `Start-Process -PassThru`
to get the pid; Stop-Process skips the tray cleanup, so a stale tray icon may linger until hovered (cosmetic).
