Refinement (2026-11-20), checked against the code:
- Not covered yet. README.md "Via ExternalGateway.exe (desktop app)" (README.md:108-139) describes the app for a
  person (double-click, tabs, tray) and README.md:37 the build line; nothing says how an agent starts a test build,
  finds the UI URL or which parts need computer-use.
- The UI is a local web page served by the app itself: `http://127.0.0.1:<port>/?s=<session>` (main.go uiURL),
  opened in an Edge `--app` window (win.go openWindow). Port and session are written to `<data-dir>\instance.json`
  (main.go:104-105); the page sends the session as `X-Session` (ui.html:103-107). So opening that URL in Chrome
  shows the real app over its real backend, not a harness.
- Single instance per data dir (win.go acquireSingleInstance): a second start only asks the running one to reopen
  its window (main.go signalRunningInstance), so a freshly built exe would not run while the owner's instance is up
  (one was running at refinement time, from the repo root). Hence `--data-dir <scratch> --port <n> --tray`.
- Tray menu, notifications and icon colour live in tray.go: computer-use only.
- Admin actions go through an elevated helper (elevate.go) and UAC.
