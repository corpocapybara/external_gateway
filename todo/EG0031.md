Found refining EG0021 (2026-11-12). pathPlaceholder (internal/server/pathtemplate.go, `\{([^{}]+)\}`) matches single braces only. The live kibana.search path `/api/console/proxy?path={{index}}/_search&method=POST` (globex and acme live ops files, gitignored) matches the inner `{index}` only, so expandPathTemplate renders `path={logstash-*}/_search`. Because the text before the match ends in `?path={`, not `?path=`, the value also skips the query-escaping branch meant for `?path=` placeholders. The tracked config.example ops do not use `{{index}}`, and no other op path in the live files does (grep `path:.*{{`, 2026-11-16).

Refined 2026-11-16: the rendering bug is proven from the code. What Kibana does with the braces (an error, or an empty result for an index named `{logstash-*}`) is recorded by the first live call (acceptance 1). The tracked change is a load-time refusal of `{{`/`}}` in op paths, so the same slip cannot come back unnoticed. The live ops edit is a local edit plus deploy.

Order: the live ops files are fixed and deployed before, or in the same deploy as, the binary that refuses `{{`; otherwise a service would fail to load its ops file. EG0021 (refined; index-scope enforcement) also edits kibana.search in the live files. This todo is independent of it and goes first or alongside.
