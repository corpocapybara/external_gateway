**`postgres.schema` has no `schema` param** (2026-11-04). Session a466da94 (10-16) got
`unknown parameter: schema`. The params are `env, db, table`, so tables outside `public` can't be described.

Refinement findings (2026-11-12): the error is ValidateParams' unknown-parameter refusal (internal/policy/registry.go:566). The schema is not hardcoded: it is the per-database Database.Schema (internal/config/config.go:130-133), used as search_path (internal/connectors/postgres/connector.go:99-100) and in the describe query built in the server, not the connector (internal/server/server.go:1389-1397, table_schema = QuoteLiteral(db.Schema)); the allowed_tables check is TableAllowed(PgAllowedTables, db.Schema, table) at server.go:1393. So the fix is server code + the op's YAML param; bucket server, also ops-config. Live operations.*.yaml are gitignored: tracked deliverable is server code + config.example/operations.globex.yaml + tests.
Proposed acceptance (pending owner answers): optional string param schema, default the db's configured schema; describe query uses it via QuoteLiteral only (injection test); schema checked by TableAllowed(pg_allowed_tables, schema, table) (public.* refuses schema=reporting, reporting.* allows it); server tests.
Owner questions: (1) agent-given schema only checked against pg_allowed_tables, or also limited to an enum/per-env list? (2) give postgres.tables the same param here, or a separate todo? (3) live cm/thp ops edits: a deploy step inside this todo, or a separate chore?

Owner answers (2026-11-12): the agent-given schema is checked only against pg_allowed_tables (no extra enum); postgres.tables gets the same param in a separate todo; the live cm/thp ops edits are a deploy step inside this todo.

Refinement round 1 (2026-11-12): the describe branch runs on a real connection (Connect at server.go:1357) and internal/server has no postgres tests, so acceptance requires two pure helpers testable without a DB, with the allow-list check done before Connect. The refusal today is a plain error from executePostgresConnector (server.go:1394), not a 403; acceptance keeps that existing path instead of claiming 403. TableAllowed lowercases (connector.go:42-50) while QuoteLiteral keeps case, so the schema param carries a lowercase-identifier pattern so case-folding cannot widen access (refinement choice, flagged to the owner). A bare allow entry (no schema) matches only public.

Refinement round 2 (2026-11-12): an empty schema="" is refused by the param pattern in ValidateParams, so only an omitted schema falls back to db.Schema; the helper still maps an empty schemaParam to dbSchema (helper-level row). Doing the check before Connect means resolving the schema branch's table/schema before Connect at server.go:1357.
