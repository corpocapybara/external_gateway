**`corpjira` can't download attachment content** (2026-11-04). Session 06e38a10 (10-23) fetched
`/secure/attachment/<id>/<name>.png` as a blob in the browser to look at a screenshot. `corpjira.attachments`
returns metadata only. Add `corpjira.attachment_content id*` (base64, size-capped, image/text types only).

**Refined 2026-11-12.** Not YAML-only: `executeHttpConnector` (`internal/server/server.go` ~752) passes a non-JSON
body through as text, so a PNG cannot reach the agent intact. Like `slack.file_content` (`internal/server/slack_file.go`,
op flag `slack_file_content`, dispatched at `server.go` ~568) it needs its own handler. The download URL
`/secure/attachment/{id}/{name}` carries no project, so an id alone would reach any attachment the token can read;
corpjira (Jira Server/DC, bearer) pins `corpjira.attachments` to `SRTHP-` keys by param pattern.

Owner decisions 2026-11-12: scope by issue key + attachment id, checked against the issue's attachment list; types
images + text + PDF; cap 1 MB per attachment; a generic op field usable by any Jira site (thp wires corpjira).

Bucket moved ops-config -> server (Go handler, registry field). Out of scope: Jira Cloud's
`/rest/api/2/attachment/content/{id}`, `proxy_host` sites, an example op in `config.example/`.
