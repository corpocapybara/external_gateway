## Problem
Agents cannot read the Gdańsk education platform (edu.gdansk.pl, Vulcan UONET+ e-diary) for the owner's child.

## Owner answers (2026-11-28)
- Scope: e-diary parent module (grades, attendance, timetable, homework, exams) and e-diary messages.
- Read-only in this slice; writes (send message, justify absence) are a later todo.
- Workspace: the owner's personal workspace (see `.ai/LOCAL.md`).
- Login: Vulcan username + password, no 2FA; a live login test during delivery is allowed.

## Findings so far
- Public login chain (WS-Federation passive, read 2026-11-28): `https://aplikacje.edu.gdansk.pl` 302 ->
  `https://cas.edu.gdansk.pl/gdansk/fs/ls/?wa=wsignin1.0&wtrealm=...` 302 -> `https://logowanie.edu.gdansk.pl/?wa=wsignin1.0&wtrealm=...cas...`
  (200, form "Nazwa użytkownika" / "Hasło"; footer "VULCAN ... CRUSTS 26.4.0.10783"; also a login.gov.pl button).
- The existing `form-session` connector (`internal/connectors/formsession/connector.go`) only POSTs `<base>/login`
  with email+password and expects a `connect.sid` cookie, so it cannot follow this multi-hop chain: a new connector is needed.
- Public reference Wulkanowy SDK (archived 2024-06): Gdańsk uses its ADFSLightCufs flow (POST Username/Password, then
  hidden-form wa/wresult/wctx hops); student module POST `*.mvc/Get` endpoints (Oceny, Frekwencja, PlanZajec,
  Sprawdziany, Homework) need X-V-RequestVerificationToken / X-V-AppGuid / X-V-AppVersion headers and per-version GUIDs;
  messages module `uonetplus-wiadomosciplus` GET `api/Odebrane`, `api/WiadomoscSzczegoly`. The live chain (cas host)
  differs from the SDK, so post-login hosts and endpoints must be mapped from a live signed-in session before acceptance.
