Split off EG0046 (2026-11-16), which shapes email responses (shapeResponse at the end of executeEmailConnector, internal/server/server.go). The other non-http connectors return unshaped: their dispatch entries (internal/server/dispatch.go connectorDispatches) return the connector's body as is. None of executePostgresConnector (server.go, returns {columns, rows, count}, rows are []map), executeLocalServiceConnector (server.go) or executeJiraWorklog (internal/server/jira_worklog.go) reads op.Response.AllowFields. Today shaping happens only in executeHttpConnector (server.go, `resp.Body = shapeResponse(...)`), executeMcpConnector (its own object-only block) and email.

Owner decision 2026-11-22: **shape** (option a). Call shapeResponse on the success body of all three, like http-rest/mcp/email, and fix the wireguard lists to the real output. Refusing allow_fields at load (option b) was rejected.

Approach: shape in dispatchConnector behind a per-entry `shape` flag (postgres, local-service, jira-worklog, mcp), not at the end of each connector function. postgres has no test DB, so the dispatch layer is the only place its shaping can be unit-tested (stub run). The flag table plus a test keeps every connector shaping exactly once.

Checked 2026-11-20/22 (all ops files in the repo root and config.example/):
- postgres and jira-worklog: no op declares allow_fields anywhere.
- local-service: wireguard.status and wireguard.test declare it in the live operations.cm.yaml (untracked; tunnels[].name/tunnels[].status and reachable), config.example/operations.globex.yaml (same lists) and config.example/operations.yaml (tunnel + peers[]..., reachable + latency_ms).
- Real local-service output: STATUS returns {tunnel, type, connected, details}; TEST returns {host, port, reachable[, error]}. The status lists match nothing (tunnels[] and peers[] do not exist), so shaping them as they are would return {} for status.

Small findings fixed along the way (hard rule; same function, needed for the TEST acceptance and the e2e):
- local-service TEST reads `params["port"].(string)`, but int params arrive as float64 (policy validation, registry.go `case "int"`), so the port is 0 and TEST always returns "host and port required".
- local-service TEST looks up the tunnel (default vpn1) before the method switch but never uses it. cm has only tunnel kko, so cm's wireguard.test (no tunnel param) fails with "tunnel vpn1 not configured".
- MCP shapes only a top-level object (executeMcpConnector unmarshals into a map); shapeResponse also handles a top-level array. Moving MCP to the dispatch flag fixes it.
- MCP behaviour after the move: a top-level array result is shaped element by element (non-object items dropped, as in http-rest) and still reaches the agent as upstream_body, because executeOp wraps only an object. A result with HTTP status >= 400 is no longer shaped (shapeResponse's error rule).
- .ai/LOCAL.md (gitignored) said "email ops are not shaped by allow_fields". That has been stale since EG0046 and was corrected on 2026-11-22.
