Split off EG0046 (2026-11-16), which shapes email responses (shapeResponse at the end of executeEmailConnector, internal/server/server.go:2639). The other non-http connectors return unshaped: their dispatch entries (internal/server/dispatch.go:32-39) return the connector's body as is, and none of executePostgresConnector (server.go:1378, returns {columns, rows, count}, rows are []map), executeLocalServiceConnector (server.go:1480) or executeJiraWorklog (internal/server/jira_worklog.go:429) reads op.Response.AllowFields. Shaping today happens only in executeHttpConnector (server.go:1086), executeMcpConnector (server.go:1300) and email.

Checked 2026-11-20 (refinement, all ops files in the repo root and config.example/):
- postgres and jira-worklog: no op declares allow_fields anywhere.
- local-service: wireguard.status and wireguard.test declare it in the live operations.globex.yaml (untracked; tunnels[].name/tunnels[].status and reachable), config.example/operations.globex.yaml (same lists) and config.example/operations.yaml (tunnel + peers[]..., reachable + latency_ms).
- Real local-service output: STATUS returns {tunnel, type, connected, details}; TEST returns {host, port, reachable[, error]}. So the status lists match nothing (tunnels[] and peers[] do not exist) and shaping them as they are would return {} for status, and strip host/port/error from test.

Owner question (open, blocks refinement): for these connectors, shape or refuse?
(a) Shape: call shapeResponse(200, body, op.Response.AllowFields) on the success body of all three, as EG0046 did for email, and fix the wireguard lists (live globex and both config.example files) to the real output. Recommended: consistent with http-rest/mcp/email, the helper exists, and postgres rows[]/worklog maps shape fine with the existing shaper.
(b) Refuse at load: policy.Load rejects response.allow_fields on postgres, local-service and jira-worklog ops (as it already does for jira_attachment_content, internal/policy/registry.go:388), and the wireguard lists are deleted. Smaller, but drops the feature and needs the live globex file edited before the next reload.

Proposed acceptance if (a): a postgres query op, a local-service STATUS/TEST op and a jira-worklog op with allow_fields return only the listed fields (unit tests in internal/server driving each connector's dispatch entry); without allow_fields the body is byte-identical to today; errors stay unshaped; wireguard lists in config.example/operations*.yaml and operations.globex.yaml name only fields the connector emits; e2e: wireguard.status through the running gateway returns tunnel and connected.

Out of scope (found work, separate todo): the MCP path shapes a top-level object only, not a top-level array (server.go:1300-1307 unmarshals into a map; shapeResponse handles arrays).
