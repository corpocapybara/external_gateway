Found in EG0042 review (correctness lane, 2026-11-14): formsession.Sessions never caches a failed login, so every request retries it. A wrong or rotated password can hammer the CodiMD account or trigger a lockout.

Checked 2026-11-16: `Sessions.Cookie` (internal/connectors/formsession/sessions.go) caches a success per `Key(workspace, site, env)` with no TTL and returns `"", err` on a failure without storing anything. `Connector.Login` (connector.go) returns plain errors for 401/403, 5xx, a 3xx to the login page, a 200 with no cookie and transport errors, with no typed error. `formSessionCookie` (internal/server/server.go) resolves the password and calls Cookie. `Sessions.Clear()` is already called on /admin/secrets set and delete and on /admin/reload, and it replaces the whole entry map, so backoff state kept in an entry is reset there with no extra code.

Proposed rule: back off only on credential refusals (401, 403, a redirect to the login page, a 200 with no session cookie), never on 5xx, transport errors or secret-resolve failures, because only refusals can lock the account. Proposed window: a fixed 60 s.

Owner questions for the design step: the window (a fixed 60 s, exponential such as 30 s up to 5 min, or a per-env config field), and whether a 200 with no cookie counts as a refusal (recommended: yes).
