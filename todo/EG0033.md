## Refinement 2026-11-13

The command is merged in ToDo (TD0191): `todo migrate-prefix --to P [--repo R]` (C:/dev/_tools/todo todofmt/prefixmigrate.py migrate_prefix). It refuses while any todo claim is live (todo/.working.json, this todo's own included), while any todo is in-progress..tested (_refuse_blockers) and while CLI edits are pending. So it runs while this todo is `designed`, after `todo commit` and after this session released its claim; then the todo is walked through the states.

Foreign ids: idrewrite rewrites every whole-token `T` + 4 digits outside moved_from/from_repo/split_from, so prose references to another repo's todos would become EG ids (ToDo TD0258, found in photo_dedup). In this repo, `git grep` for ids above the local max (35, .git/todo-maxid) finds only ToDo ids, listed here in TD form: EG0001 body (TD0185), EG0024 title and body (TD0146, TD0151), EG0027 body (TD0129, TD0169) and this body. They are reworded to TD form with `todo set` before the run (photo_dedup's workaround).

`todo done --apply` deletes a tested todo only when a non-bookkeeping commit subject on master names it (done.py IGNORED_SUBJECT skips `todo:`/`docs:` subjects, merges are skipped), so the delivery needs a branch commit naming EG0033: a one-line note in CLAUDE.md that todo ids use the EG prefix and that T-numbered ids in older history name the same todos (former_prefixes).
