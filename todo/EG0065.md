Notes from the EG0035 project review, area 6 (docs/review/2026-11-project-review.md, R13). Split from EG0057.

Facts checked 2026-11-20:
- internal/audit/logger.go Logger.Log rotates audit_<date>.log by size (max_size_mb) but nothing ever deletes a file.
  Live: C:\ProgramData\external_gateway\audit holds 104 files, 118 MB (2026-07-08 .. today).
- Every deployed config (config.*.yaml) points audit.dir at the same C:\ProgramData\external_gateway\audit, so all
  egw-<x> services write and would prune the same folder (same file names, appended per record).
- cmd/egw/main.go main builds the operational logger as zerolog.New(os.Stderr) before the config is loaded; under the
  SCM stderr goes nowhere. The review measured 18.9 MB of stderr log per 20,000 requests.
- audit.Init runs once per process (globalLogger guard); /admin/reload does not re-init audit, so audit settings
  apply from the startup config (as dir and max_size_mb do today).
- Nothing else in the repo reads the audit folder (grep for audit dir readers: only internal/audit).

Owner decisions (2026-11-20, in chat):
1. Audit retention: optional `audit.retention_days`, default 90 when unset, 0 keeps everything; prune
   audit_<date>[_n].log files whose name date is older, at startup and on the first record of a new day.
2. Service log: when running under the SCM, also write the zerolog output to a size-rotated file
   `C:\ProgramData\external_gateway\logs\<svc-name>.log` (optional `log.file` override in config), its rotated
   files pruned by the same retention days. Not the Windows Event Log.

Several services share one audit folder and may prune it at the same time: a file already removed by another
service is not an error; with different retention_days the shortest effectively wins (documented, not prevented).
