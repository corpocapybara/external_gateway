Notes from the EG0035 project review, area 6 (docs/review/2026-11-project-review.md, R13). Split from EG0057.

Facts checked 2026-11-20:
- internal/audit/logger.go Logger.Log rotates audit_<date>.log by size (max_size_mb) but nothing ever deletes a file.
- Every deployed config (config.*.yaml) points audit.dir at the same C:\ProgramData\external_gateway\audit, so all
  egw-<x> services write and would prune the same folder (same file names, appended per record).
- cmd/egw/main.go builds the operational logger as zerolog.New(os.Stderr); under the SCM stderr goes nowhere.

Open owner questions (todo stays draft until answered):
1. Audit retention: how many days to keep, and on by default? Proposal: optional `audit.retention_days`
   (default 90; 0 keeps everything), pruning audit_<date>[_n].log files whose name date is older, at startup and
   on the first record of a new day.
2. Service log destination. Proposal: when running under the SCM, also write the zerolog output to a size-rotated
   file `C:\ProgramData\external_gateway\logs\<svc-name>.log` (optional `log.file` override), kept by the same
   retention. Alternative: the Windows Event Log through kardianos/service's logger.
