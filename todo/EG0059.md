Created 2026-11-16 by EG0058's review: its history tests raised the leakcheck package from 23.8 s to 34.5 s.

Measured 2026-11-20 (refinement, master 2256c77): `go test -count=1 -v ./cmd/tools/leakcheck/` wall 31.8 s, package line 17.4 s,
TestHistoryLeakyRepo 9.31 s (next slowest TestHookChainEndToEnd 3.32 s, out of scope). A logging git shim on PATH
counted 112 git processes for `-run TestHistory`: 13 runHistory/run calls (13 `log`), 17 `ls-tree`, 26 `for-each-ref`,
15 `cat-file`, 19 `rev-parse` (8 `head()` calls, 11 mainCheckout), and ~25 setup calls (`add`, `commit`, `rm`).
At ~80 ms per git process on this machine, the cost is the process count, not the scan.

Approach (settled in refinement, test-only):
- Setup: build the 8 commits with one `git fast-import` run into the newRepo repo (same files, messages, author and
  committer identities, CRLF content), read c0..c7 with one `git rev-list --reverse main`; `git tag -a` and
  `git branch` after the clean run as today.
- Runs (13 -> 5): run(history c0) clean + dispatch; -root absolute and relative on c0; after the tag and branch,
  hist(c3..c7) (REV limit: c4 message, c5/c6 identities, c7 blob and message in; c1 blob and c3 path out; tag and ref
  in); hist(-allow FILE) over all history. The redundant per-surface range runs and the duplicate c0 run go: the
  whole-history lines they asserted are each asserted in one of the remaining runs.
- Production code (runHistory's per-tree `ls-tree` and its two `for-each-ref` calls) is not changed here.
