Created 2026-11-16 while refining EG0048 (history rewrite), by owner decision in chat: EG0048's proof that git history holds no real names needs a scan over every blob, path, message and identity of every commit. The owner chose a `history` subcommand of the existing leakcheck tool (EG0047, design `docs/design/EG0047-leakcheck-hook.md`) over a throwaway script, so the scan reuses its terms file (`.ai/leakcheck-terms.txt`, gitignored, plus non-public config hosts) and its matcher (`matchTerms` / `lineHits` in `cmd/tools/leakcheck/leakcheck.go`), and stays usable when a leak turns up later.

Why a tool: Git Bash's `grep` 3.0 aborts (SIGABRT, exit 134) on `-i -F` with more than one pattern (`echo hello | grep -i -F -e foo -e bar`, checked 2026-11-16), so a shell pipeline cannot do a case-insensitive multi-term scan on this machine.

Scale measured 2026-11-16: 564 commits reachable from `--all`; a Python prototype of the same matching over `git log --all -p` added lines, messages, paths and identities finds hits for 9 terms (7 from the terms file, 2 config hosts) and none in identities.

EG0048 runs it with `-root <main checkout>` on a mirror and on a rewritten clone outside the main checkout, and with `-allow` naming the exact historical email carbon-copy field lines (the two-letter workspace name is also that field's name).

Design choices settled in the acceptance (no separate design): commits from `git rev-list`, files per commit from `git ls-tree -r -z`, each distinct blob read once (`git cat-file --batch`); terms and matching exactly as pre-commit (design D4, D5).
