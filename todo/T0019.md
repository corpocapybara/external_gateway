Found in T0003 review (correctness note, 2026-11-11). CheckConstraints (internal/policy/registry.go) has no default case and loadFromFile does not check constraint types, so a typo such as jira_field or jql_scop silently drops the guard (for jira_fields, any list then passes, since ValidateParams has no list case). Proposed acceptance: loadFromFile refuses an unknown constraint type naming the op and type; a test loads every config.example ops file to prove none is refused.
