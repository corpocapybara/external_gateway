**Problem.** The repo is public, yet nothing stops a commit from naming a real workspace, project, customer
or internal host: the real names live only in gitignored files (`.ai/LOCAL.md`, `config.<x>.yaml`), and agents
copy them into todos, design docs, tests and commit messages. Goal: let no new mention of an actual
project/workspace sneak through a commit.

**Owner answers (2026-11-16):**
- Term source: a gitignored hand-kept terms file plus the hosts read automatically from the gitignored
  `config.*.yaml` files of the main checkout.
- What is checked: only the lines a commit adds, newly added/renamed/copied paths, and the commit message.
- Existing mentions in the tracked tree are left alone here (no new scrub todo); EG0038 (tree) and EG0048
  (history) already cover them.
- Built as a Go tool with an inline allow marker for deliberate false positives.

**Shape.** A Go command `cmd/tools/leakcheck` with subcommands `pre-commit`, `commit-msg <file>` and
`install`. `install` copies the built checker into the shared hooks dir (`git rev-parse --git-common-dir` +
`/hooks`) and writes `pre-commit.local` and `commit-msg.local`, which the todo tool's managed hooks run first
(todo DESIGN.md 4.4), so the existing todo hooks keep working and all worktrees share the check.

**Terms.** `.ai/leakcheck-terms.txt` (gitignored, next to `.ai/LOCAL.md`): one term per line, blank lines and
`#` comments ignored. Plus the host of every `http://`/`https://` URL in the main checkout's `config.*.yaml`,
minus a built-in list of public service hosts (e.g. `api.github.com`, `slack.com`) and loopback hosts.
Matching is case-insensitive; a term edge that is a letter/digit/underscore must sit at a word boundary, so a
short token does not hit inside a longer word. A short token that also is an ordinary word (e.g. an email
`cc` field) is the owner's choice to list; deliberate hits take the allow marker.

**Risk:** low (no public API, persistence, concurrency or other bucket: `cmd/tools/`, its README, `.gitignore`).

**Refinement round 1 (2 lanes) dispositions:** rejected: git not on PATH (hooks run from git), bare or
separate git-dir layouts (the install target is this repo's main checkout; a missing terms file fails closed),
writing core.hooksPath support (install refuses instead). Notes for design: the todo tool's own commits and
web-page commits pass through the same hook; a clean `git merge` runs no pre-commit at all.

**Out of scope:** scrubbing the current tree or history; CI/server-side checks; checking files the commit
does not add lines to.
