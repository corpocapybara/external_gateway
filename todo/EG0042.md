Split out of EG0041's refinement (owner 2026-11-14: "wire form-session in"). EG0041 makes loadFromFile refuse any connector outside the dispatch set. The 3 CodiMD ops in config.example/operations.yaml (codimd.notes, codimd.note and a third, ~lines 1328-1360) use `connector: form-session`. Tests load that file, so EG0041 waits for this todo.

Facts (2026-11-14, master f9913c0+):
- internal/connectors/formsession/connector.go implements Login (POST <base>/login, form email+password, keeps the `connect.sid` cookie) and Execute (sends the request with that cookie, body cap 20 MiB).
- It is not in the dispatch chain in internal/server/server.go (~568-585), and .ai/CONNECTORS.md:42 says so. Today an op with this connector falls through: empty body, status 0, audited as allow.
- One Connector instance holds a single session cookie and base URL in plain fields: no per-workspace or per-site separation, no locking, no re-login when the session expires.

Open for refinement and design: the credential shape (email + password in Credential Manager under egw/<workspace>/<name>?), a per workspace/site session cache with cross-tenant isolation (internal/secrets/resolver.go), concurrency, re-login on 401 or redirect to /login, response shaping like http-rest, and tests against an httptest server.
