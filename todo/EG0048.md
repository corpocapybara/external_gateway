Split off EG0038 by the owner (2026-11-16): EG0038 removes the real workspace names and the real Jira project key from the tracked tree; this todo removes them, and every other leak term, from git history. The names are listed in the gitignored `.ai/LOCAL.md` (section "Real names in tracked files") and in the leakcheck terms file `.ai/leakcheck-terms.txt` (gitignored, EG0047); never write them into a tracked file, this one included.

The repo is PUBLIC on GitHub (origin), so a rewrite means:
- a string replace over all history (`git filter-repo`: `--replace-text` for blobs, `--replace-message` for commit messages, a path rename for file names), every SHA from the first hit on changes;
- a force-push of master; live worktrees and branches of other sessions must be finished first (start condition);
- GitHub keeps old SHAs reachable (refs/pull/*, forks, cache) until a GitHub Support purge request; old SHAs cited in todos, handovers, design docs and commit messages go stale (the kept commit-map translates them);
- tool-owned todo fields (history notes, from_repo, frozen acceptance) and handovers that still name them are rewritten by the same pass. Other clones of the repo must be re-cloned after the force-push.

Owner decisions (2026-11-16, in chat): refinement reviews run until green (round 4+ allowed past the 3-round cap); force-push: GO once the todo is unblocked (start condition met); GitHub Support purge request: the owner files it, and its id is added to this body when the owner gives it; the history scan is a new `leakcheck history` subcommand (EG0058, a blocker of this todo), not a throwaway script; the rewrite purges every leakcheck term that hits history, not only the LOCAL.md names and EG0049's strings.

Facts checked 2026-11-16 (refinement round 4):
- 564 commits are reachable from `--all`; no tags, no notes, empty stash; no leak term in any author or committer identity. Local master is ahead of origin/master, so the backup mirrors the main checkout after master is pushed, not origin alone.
- A prototype of leakcheck's matching (terms file plus non-public config hosts, as `loadTerms`) over every added line, message, path and identity in history hits 9 terms: the four LOCAL.md names (the three-letter workspace name in about 594 added lines, 35 message lines and 3 paths), three more terms from the terms file and two real config hosts (one of them EG0049's host). EG0049's other string (a search value, a first name) is not a term and has 1 added-line hit; it is added to the local terms file for the scan. So the rewrite covers all leakcheck terms, not only the LOCAL.md section.
- The three-letter workspace name is a substring of common identifiers (unbounded matches run into the thousands) and of the Jira key: replacement rules must be word-bounded and replace the Jira key first.
- The tracked tree outside todo/ and handovers/ has new hits again: EG0011 (delivered after EG0038) wrote one workspace name into `.ai/OPERATIONS.md` (jenkins.build_with_params row) and `internal/server/jenkins_build_params_test.go` (a comment). The rewrite covers them, so the new master tree differs from the old one in those lines too.
- The two-letter workspace name is also the email carbon-copy field name, in code, config and prose (in `config.example/operations.yaml`, `internal/connectors/email/connector.go`, `internal/server/email_shape_test.go`, commit messages and todo text). The field lines must survive unchanged: they are collected exactly into the ALLOW file outside the repo (never tracked, since the term is a real name), and the rules exempt them (how: the design step); prose that names the workspace is replaced. The dry-run push and the gh permission and protection queries prove the URL, write access and no branch protection, not the forced update itself; no probe branch is pushed to the public repo.
- `.ai/shared/` (hard-linked across repos) has no hit at HEAD. The main checkout carries uncommitted edits to hard-linked `.ai/shared` files from other repos; git filter-repo ends with `git reset --hard` and refuses a non-fresh clone, so it runs in a fresh clone of the mirror, and the main checkout moves without `reset --hard` (TD0293).
- After the move the main checkout still holds the old objects locally (reflogs, unreachable objects); `leakcheck history` reads refs only. They are never pushed; expiring them (`git reflog expire --expire=now --all`, `git gc --prune=now`) is left to the owner, since it also drops the local undo.
- Git Bash's `grep` 3.0 aborts on `-i -F` with more than one pattern, hence the Go scan (EG0058).
- git-filter-repo is not installed (installing it is a download, asked at implementation).
