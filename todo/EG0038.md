RULES.md "HARD RULE — no real workspace identifiers in tracked files": a tracked file that names a real workspace is a bug. The real workspace names and Jira project keys, the check pattern and the placeholders are in the gitignored `.ai/LOCAL.md`, section "Real names in tracked files"; this todo never writes them into a tracked file.

Measured 2026-11-16 on master (aab7f53): the pattern hits 34 tracked files outside todo/ and handovers/ (2 of them are the email `cc` field, not leaks): `.ai/OPERATIONS.md` (the attachment-content row and section, a JQL example, an edit example), `README.md` (workspace table and a section on one live workspace), `docs/` (SLACK, WORKLOG, CLOCKIFY, archive/todo-md-migration, design docs EG0003/EG0008/EG0013/EG0014/EG0019, the EG0014 file name), `deploy/set-gitlab-token.ps1` (default `-Workspace`), `tools/slack-provision/Provision-Slack.ps1` (a comment), `internal/server/jira_worklog.go` (a comment and the error text "issue key like <KEY>-123"), 18 Go test files in internal/server, internal/policy, internal/config, internal/audit, internal/tokencheck and cmd/egw-desktop. `.ai/RULES.md` names one in its grep example. Also: `.ai/OPERATIONS.md` cites old ids T0008 (§Jira attachment content), T0021 (kibana_index_scope row), T0014 (Jira write ops heading); migration commit 50d3a10 renamed T00NN to EG00NN one to one. `.ai/PITFALLS.md` "PowerShell 5.1 UTF-8 corruption" restates the global core rule "Windows PowerShell 5.1 corrupts UTF-8".

Owner decisions (2026-11-16, chat):
- History is NOT rewritten here: EG0048 (blocked by this todo) rewrites history and force-pushes.
- Scope: every tracked file, Go tests included; the other real workspace names (same kind) are included.
- cmd/egw-desktop tests that copy the real gitignored root configs pick the workspace at run time: the first `config.<ws>.yaml` at the repo root (sorted) that has an `operations.<ws>.yaml`, plus every root `operations*.yaml` for the catalog; skip when none. TestPatchedRealConfigsUnchangedRoundTrip globs the root `config.*.yaml` / `operations.*.yaml` the same way. Refinement round 1 (tests lane): the first such workspace here has no role named like the one the add-service test hard-codes, so that test grants the workspace's first sorted role; the round-trip test skips instead of passing when it finds no file.
- todo/ and handovers/: only bodies and titles of todos no other session holds, through `todo set`. Left to EG0048: held todos, tool-written fields (history notes, from_repo), acceptance, handovers (no CLI edit; pruned when their todos close).
- deploy/set-gitlab-token.ps1: `-Workspace` becomes Mandatory with no default. Same kind, done too: `-Port` (default is that workspace's real port) becomes Mandatory.

Placeholders follow RULES.md (`<ws>`, or the illustrative acme/globex); the mapping is in LOCAL.md. OPERATIONS.md's attachment-content row describes a gitignored live op: the row is generalised (placeholders) and its live-only detail goes to LOCAL.md.

Risk: high (crosses buckets server, cli-tools, deploy, docs). Design: not needed — the owner settled every trade-off above; no public API, schema or cross-bucket interface change (an error-message example key and two script defaults only); no open questions.
