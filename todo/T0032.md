Add the same optional schema param as T0010 (checked only against pg_allowed_tables, QuoteLiteral only, live cm/thp ops edit as a deploy step). Do after T0010 and reuse its check.

Refinement findings (2026-11-12): the tables branch (server.go:1380-1387) runs SELECT table_name, table_type FROM information_schema.tables WHERE table_schema = QuoteLiteral(db.Schema) on a live connection (Connect at server.go:1357), then FilterTableRows(result, PgAllowedTables, db.Schema) (internal/connectors/postgres/connector.go:109). Unlike postgres.schema there is no table to check before Connect: the allow-list is applied as a row filter, so an agent-given schema is safe once the filter uses the same resolved schema as the query. The allowed_tables op constraint is a no-op marker (internal/policy/registry.go:275); the real check is in the server. An unknown param is refused by ValidateParams (registry.go:566), so today schema is rejected. Pattern validation of an empty string runs (registry.go:486-493), so schema="" is refused and only an omitted schema falls back. Live ops: operations.cm.yaml:1195 and operations.thp.yaml:2060 define postgres.tables with params env, db. Blocked by T0010 (its resolution helper and pattern are reused).
