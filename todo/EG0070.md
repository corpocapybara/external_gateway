Found 2026-11-20 while delivering EG0059 (history test speed-up).

`runHistory` (cmd/tools/leakcheck/history.go) runs `git ls-tree -r -z --full-tree <tree>` once per distinct root tree
of the listed commits, one `git cat-file tag` per annotated tag, and two `for-each-ref` calls (tags, then all refs).

Measured 2026-11-20 on this repo (742 commits; `leakcheck history -root <dir with a no-match terms file>`): 29.1 s,
718 git processes (714 `ls-tree`, 2 `for-each-ref`, 1 `log`, 1 `cat-file`). Reading every reachable object
(1765 trees, 1538 blobs, 742 commits) through one `git cat-file --batch` takes about 2 s, so the cost is the process
count.

Approach (settled in refinement):
- One `git --no-replace-objects cat-file --batch` process, started at the first read and driven request by request
  (write an object id, flush, read the header and content), reads tree objects, blobs and refs/tags objects. A
  `missing` header, a header type other than the one expected (tree for a root or mode-40000 entry, blob for a
  file), a malformed or truncated tree, or a non-zero exit of the process is an error (exit 1), as `ls-tree` failing
  is today.
- Trees are parsed from the raw tree format (`<octal mode> <name>\0<raw hash>`, hash length = len(object id)/2:
  20 bytes sha1, 32 sha256) and walked depth-first in stored order, the order `ls-tree -r` lists. The mode is parsed
  as octal and masked with 0170000, as git's S_ISDIR / S_ISGITLINK: 0040000 recurses (legacy `40000` too),
  0160000 (gitlink) is skipped, anything else (100644, 100755, 120000 symlink, legacy 100664) is a blob. Parsed
  entries are cached per tree id; a (path prefix, tree id) pair already walked is skipped, since all its paths and
  blobs were already seen and attributed (first commit in log order, first path in tree order), so output is unchanged.
- One `for-each-ref --format=%(objectname) %(refname)`, which reads no object (checked: a dangling refs/heads ref is
  listed, exit 0; `%(objecttype)` would die on it), gives every ref name for the ref surface. Refs under `refs/tags/`
  are read through the cat-file process: a `tag` object is parsed as today (the raw content is what `cat-file tag`
  printed), any other type is not a tag; a missing object is an error, as `for-each-ref %(objecttype) refs/tags`
  fails today.
- The README's surfaces, output and limits do not change.
